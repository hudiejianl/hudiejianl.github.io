Git 使用指南：从入门到常用命令速查

2026/2/20 教程 Git 工具

1. Git 是什么：你在解决什么问题

Git 是分布式版本控制系统，核心能力是：

  • 跟踪文件变更（历史记录）
  • 安全协作（分支、合并、Pull Request）
  • 随时回到过去（撤销、回滚、对比）

术语速记：

  • Working Tree：工作区（你当前编辑的文件）
  • Staging Area：暂存区（git add 进去的变更）
  • Repository：本地仓库（git commit 形成的历史）
  • Remote：远程仓库（GitHub/GitLab）

如果你只想“先把日常用法跑通”，可以先看这几个最常用命令：

  • git status
  • git add .
  • git commit -m "..."
  • git pull
  • git push

2. 第一次使用：安装与基础配置

2.1 检查 Git 是否可用

git --version

2.2 配置用户名和邮箱（会写进提交记录）

git config --global user.name "hudiejianl"
git config --global user.email "you@example.com"

查看配置：

git config --global --list

2.3（推荐）设置默认分支名为 main

git config --global init.defaultBranch main

3. 新建仓库 / 克隆仓库

3.1 在当前目录初始化仓库

git init

3.2 克隆远程仓库

git clone https://github.com/<user>/<repo>.git
# 或 SSH：
# git clone git@github.com:<user>/<repo>.git

4. 最常用的日常流程（必会）

4.1 查看状态与差异

git status

git diff            # 工作区 vs 暂存区

git diff --staged   # 暂存区 vs 最后一次提交

4.2 暂存与提交

git add .
# 或精确到文件：git add path/to/file

git commit -m "feat: add git guide"

4.3 查看提交历史

git log

git log --oneline --decorate --graph --all

4.4 拉取与推送

git pull

git push

建议：pull 默认可能是 merge，也可能是 rebase，取决于你的配置；团队统一即可。

5. 分支（branch）：并行开发的核心

5.1 查看/创建/切换分支

git branch              # 查看本地分支

git branch -a           # 查看所有分支（含远程）

git switch -c feature/login   # 创建并切换到新分支

git switch main               # 切换分支

老命令等价写法：

git checkout -b feature/login

5.2 合并分支（merge）

把 feature/login 合并进当前分支：

git switch main
git merge feature/login

5.3 变基（rebase）：让历史更线性

常见用法：把当前分支“追上”主分支：

git switch feature/login
git fetch origin
git rebase origin/main

发生冲突：

  • 解决冲突后
git add .
git rebase --continue

放弃 rebase：

git rebase --abort

建议：

  • 公共分支（大家都在用的分支）尽量不要随意 rebase（会改历史）
  • 个人 feature 分支 rebase 很常见，能保持历史干净

6. 远程仓库（remote）：GitHub 协作

6.1 查看远程

git remote -v

6.2 添加远程

git remote add origin https://github.com/<user>/<repo>.git

6.3 推送本地分支到远程并建立追踪

git push -u origin main
# 推送当前分支：git push -u origin HEAD

6.4 只拉取不合并

git fetch origin

7. 撤销与回滚（高频！）

7.1 撤销工作区改动（未 add）

git restore path/to/file
# 全部：git restore .

7.2 取消暂存（已 add，但未 commit）

git restore --staged path/to/file
# 全部：git restore --staged .

7.3 修改最近一次提交信息（未 push 时最安全）

git commit --amend

7.4 回退到某个历史（reset）

  • 只回退提交指针，保留工作区（常用）
git reset --soft <commit>
  • 回退提交指针，保留工作区但清空暂存
git reset --mixed <commit>
  • 危险：连工作区一起丢掉
git reset --hard <commit>

如果你已经 push 到远程，谨慎用 reset 改历史；推荐用 revert。

7.5 反做一个提交（revert，适合已 push）

git revert <commit>

revert 会生成一个新的提交来抵消旧提交，历史不会被“重写”。

8. 暂存现场（stash）：临时切分任务

git stash push -m "wip: half done"

git stash list

git stash pop    # 应用并删除
# 或：git stash apply 只应用不删除

9. Tag：发布版本

git tag

git tag v1.0.0

git push origin v1.0.0
# 推送所有 tag：git push origin --tags

10. 冲突怎么解决（实战流程）

出现冲突时 Git 会把冲突文件标记出来：

  1. git status 看冲突文件
  2. 打开冲突文件，手动选择保留内容
  3. git add .
  4. 根据你正在执行的操作：
    • merge：git commit
    • rebase：git rebase --continue

11. 常用命令速查表

11.1 状态 / 日志 / 差异

git status

git log --oneline --decorate --graph --all

git diff

git diff --staged

11.2 分支

git branch

git switch -c <name>

git switch <name>

git merge <name>

git rebase <upstream>

11.3 远程

git remote -v

git fetch origin

git pull

git push

11.4 撤销

git restore .

git restore --staged .

git commit --amend

git revert <commit>

git reset --soft|--mixed|--hard <commit>

12. 推荐一个“够用”的协作工作流

  • main：稳定分支
  • 开发新需求：git switch -c feature/xxx
  • 开发中频繁提交（小步提交）
  • 发 PR / 合并：用 merge 或 squash merge（团队统一）
  • 合并后删除 feature 分支
